# RMS financial-data and SSOT audit

Reviewed baseline: `93c91f8e50e9476232699fea62329cc812a4ab30` on GitHub `main`. Date: October 26, 2026 (Asia/Seoul).

The Wheat mismatch was caused by two display paths: the summary used the saved dated Frankfurter FX packet, while class cards, absolute weekly/monthly changes, chart points and 52-week ranges used a literal USD/EUR divisor of **1.08**. At USD 229.64, the fixture's actual USD→EUR factor 0.89342 gives EUR 205.16; dividing by 1.08 gives EUR 212.63. These numbers are regression inputs, not new production quotations.

The review also found fabricated observations outside Wheat. They were not retained as outage fallbacks. The existing modern scheduled Gemini implementation, its policy files, Secret configuration, cloud adapters, Job/Scheduler configuration and deployment files were not modified. No deployment, cloud mutation or paid provider test was performed.

## Scope and evidence

The audit searched tracked application source, source metadata, stored-data interfaces, service consumers, configuration and tests. It traced browser rendering and legacy server entry points rather than treating every numeric literal as a market observation. Untracked backups/research archives and local secrets were not rewritten. Existing local changes to `server.ts`, `publicViewer.ts` and USDA JSON records are excluded from this commit.

[RMS_FINANCIAL_DATA_AUDIT_INVENTORY.json](RMS_FINANCIAL_DATA_AUDIT_INVENTORY.json) records **1,425 original candidates**, with original file/line, expression or narrative excerpt, candidate category and disposition. It includes harmless candidates so that exclusions remain reviewable. It is a provenance inventory, not a claim that all 1,425 literals were defects. The file-specific resolutions below cover the problematic groups. The read-only generator is `scripts/audit/financial-data-inventory.mjs` and accepts an extracted baseline checkout.

## Preserved exceptions and limitations

- **Dated observations are not prohibited literals.** Existing JSON history/receipt stores, `src/data/wheatHistory.ts` (imported historical baseline), `src/data/potatoProductionHistory.ts` (approved manual annual raw-potato history with Actual/Estimate/source/coverage) and `soybeanOilEvidenceService.ts`'s explicitly dated EIA context are preserved. Manual-import records are not newly certified as independently verified. Baseline-only Wheat data is excluded from the current quote selector, while its historical record remains accessible.
- Existing original-publisher news/editorial records contain dated numeric quotations and supporting receipt requirements; they remain historical evidence, not synthesized live prices. Their factual content was not re-authenticated through external providers in this task.
- Unit constants (bushels/MT, pounds/MT, cents-to-dollars, area/weight conversions), percentages/rounding, chart dimensions/padding/range denominators, source coordinates, crop thresholds, source/schema IDs, time windows, security quotas and explicit operating/AI request policies are preserved. The remaining `high * 1.08` in chart geometry is 8% axis padding, not an FX rate.
- Missing-value sentinels such as zero price in instrument metadata or NaN in an unavailable typed supply record are not displayed as observations. Oil area/yield is explicitly N/A, not claimed zero production. Rainfall aggregation sums zero contributions for missing days only while retaining coverage counts and withholding complete-period metrics until required days exist.
- Deterministic risk/strategy thresholds and quality/evidence scoring are documented model/configuration values, not live observations or guaranteed financial outcomes. The legacy fixed macro-risk assembler is disabled. No new pricing or FX assumption was introduced.
- The AST guard protects known prohibited literal/fallback/conversion/randomness patterns and startup behavior. It supplements consumer/provenance review; it is not a mathematical proof of semantic correctness for arbitrary future code. The only source-history files exempted from its financial-property-literal check are the documented raw-potato annual and Wheat weekly manual-import histories.
- Legacy compatibility factories that previously invented data now return unavailable errors; callers must use existing saved-source routes. This is intentional removal of unsupported data behavior. Modern accepted Gemini analysis remains available, including during outages.
- Deployed configuration, actual provider availability, billing and browser interactions were not verified or changed. No financial-source raw-data files or user-owned local changes are included in the commit.

## Regression protection and executed validation

New `wheatCurrencyConsistency.test.tsx` renders actual Overview/detail/components. It checks all eight commodities × USD/EUR/KRW; Wheat SRW/HRW/HRS cards and absolute weekly/monthly moves; chart endpoint labels; 52-week current values; timestamp ownership; competing cache isolation; later FX updates; source immutability; contradictory metric/history rejection; source outages and missing FX without NaN/Infinity or invented prices. Palm/Potato established conversion results remain covered.

New `financialDataSsot.test.ts` scans tracked runtime TypeScript/TSX/MJS for prohibited financial literals, numeric/string fallback prices, hardcoded FX expressions and random observations. It exercises empty startup, retired unsupported adapters, no missing-FX substitution, strict calendar/retrieval dates and rejection of baseline-only current Wheat data. Existing canonical-selector tests now update source metric/history consistently; FX outage tests require the retained/stale flag.

TypeScript (`npm run lint`), production build (`npm run build`), whitespace checks and the new/related financial-data tests passed. The build retains its large-chunk advisory. All tracked server test programs plus the two new programs executed **118 programs: 67 passed, 51 failed**. All 51 remaining failures also failed against the pre-change committed source in a separately extracted baseline checkout, using the same local fixtures. The initial broad run had 52 failures; the missing-FX Palm test now passes. No previously passing test in the broad run regressed. Existing baseline failures include obsolete protected-file hashes, snapshot directory assumptions, old fixture expectations, weather freshness expectations and unrelated editorial/evidence checks. They were not suppressed or reported as successful.
